## 2. 입력은 둘뿐 — 프로토타입과 요구사항

| 입력 | 무엇을 정하나 | 어디서 온다 |

| 프로토타입 | 디자인과 인터랙션: 랜딩 덱, 펼친 카드 = 테스트 무대의 창, 공통 셸, 무대 I·J·D, 시작 전 안내 모달, 공유·투표, 모션, 테스트 대표색 | 병렬 세션의 최종판(V4)과 사용자의 1–3차 판정 원문 |

**레거시 코드는 입력이 아니다.** `legacy/v2` 는 요구사항이 모호할 때 「무엇을 해야 했는가」를 확인하는 조회용이다. 예컨대 locale 별칭 표는 코드에만 정확히 적혀 있다. 가드 테스트·함정 원장·방어 분기·구현 패턴은 옮기지 않는다. 스택 함정 지식(Next 16·WebKit·Playwright)은 옮기지 않고 **그 함정이 생길 수 없는 구조**를 고르는 데만 쓴다.

- 배경 모션과 스프링·패럴랙스를 허용한다(`req-landing` §1.3, 옛 `design.md` 금지 조항을 대체).

## 3. 새 main 의 모습 — 최종 아키텍처 요약

### 3.1 스택

- **런타임:** Next.js `16.3.6`, React `19.3`, next-intl `4.14`(메시지와 ICU 서식만), zod `4`(신뢰 경계의 codec).
- **스타일:** 순수 CSS + native cascade layer 한 벌. 진입점은 `src/ui/index.css` 하나다.
- **검증 도구:** vitest(node), Playwright(`mobile-webkit` 이 주력), ESLint + stylelint.
- **쓰지 않는 것:** Tailwind, CSS Modules, 애니메이션 라이브러리, 상태 라이브러리, next-intl 라우팅, parallel·intercepting route.
- **Next 판을 고정하는 이유:** `next/og` 원격 코드 실행 권고 `GHSA-vcvr-r3jv-pc5j` 가 `< 16.3.6` 에 걸린다.

### 3.2 디렉터리와 계층

|:---|:---|:---|

### 3.3 창(펼친 카드 = 무대의 창)

- **구조.** 랜딩은 마운트된 채 남고, 창은 그 위의 클라이언트 층이다.
- **history.**
  - 카드를 열면 `/{l}#{v}` 를 push 한다.
  - Q1 에 답하면 `/{l}/test/{v}` 로 replace 하고 창이 전체 화면으로 자란다.
  - 모든 퇴장(닫기·바깥 탭·Esc·워드마크·시스템 뒤로가기)은 `history.back()` 하나로 모인다.
  - popstate 수신자 한 곳만 창을 닫거나 같은 카드로 줄인다.
- **깊은 링크.** `/{l}/test/{v}` 로 바로 들어오면 같은 테스트 경험이 전체 화면으로 열린다.
- **intercepting route 를 기각한 이유.** 심사 에이전트가 Next 16 소스를 읽고 확인한 세 가지 때문이다.
  - 뒤로가기로 닫을 때 슬롯 내용이 즉시 사라진다.
  - popstate 전환은 애니메이션되지 않는다.
  - 이 둘 때문에 사용자가 3차에서 승인한 「내용을 보인 채 같은 카드로 줄어들기」를 만들 수 없다.

### 3.4 요구사항이 방어 코드 없이 들어가는 방식

- **검증은 네 신뢰 경계에서만 한다.** URL, 저장소, 네트워크, 콘텐츠 빌드다. 경계를 통과한 값은 타입으로 보장되고 다시 검사하지 않는다.
- **콘텐츠는 빌드 때 컴파일한다.** 잘못된 콘텐츠는 빌드가 실패하므로 배포될 수 없다. 그래서 레거시의 런타임 지연 검증, 변형별 폴백, 파생 실패 화면은 **도달할 수 없어 만들지 않는다.** 이 목록은 `DECISIONS.md` 에 기록한다.
- **진행 규칙은 순수 함수 하나다.** 형태는 `step(state, event) → { state, effects }` 이고, 전이표가 명세의 정본이다. 「Esc 는 아무것도 쓰지 않는다」는 `effects.length === 0` 이라는 테스트 한 줄이 된다.
- **이미 퍼진 링크를 깨지 않는다.** 결과 URL codec 과 저장 키 셋(동의·테마·기록)은 레거시와 바이트 호환이다. 그래서 이미 공유된 결과 링크와 재방문자의 설정이 이전 코드 없이 그대로 통한다.

### 3.5 디자인 시스템 v3

- **토큰은 `src/ui/tokens.css` 한 벌이다.** 앱이 직접 읽고 Claude Design 에는 바이트 그대로 올린다. 사본이 없으므로 패리티 가드도 없다.
- **테스트 대표색은 토큰이 아니라 콘텐츠 데이터다.** 7개 대비 불변식(PAL-1…7)이 빌드 규칙으로 걸린다.
- **Claude Design 에는 번들 스크립트가 만든 산출물만 간다.** 번들은 specimen(컴포넌트마다 한 파일)을 정적 HTML 로 굳힌 것이다. 새 프로젝트의 파일 집합은 `BUILD.json` 과 항상 같다.

### U7 — 착지와 동결의 원자성

1. **P 확정.** `origin/main` 의 끝이 P 다(U0 가 착지했다면 그 커밋). P 의 프로덕션 배포가 `success` 인지 확인하고 프로덕션 지문 F0 를 잰다.
2. **squash.** `claude/rebuild-foundation` 을 main 에 squash 해 커밋 S 하나를 만든다. S 의 부모는 P 이고, S 의 트리는 레거시 추적 파일을 하나도 갖지 않는다. 이 계획서는 같은 커밋에서 `docs/done/` 으로 옮기고, 조사·아키텍처 원문을 그 옆에 기록으로 싣는다.
3. **원자적 push.** main, `legacy/v2`, `legacy/v2-final`, `prototype/mobile`, `prototype/mobile-final` 을 `git push --atomic` 한 번으로 올린다. main 이 거부되면 아무 ref 도 생기지 않으므로 legacy ref 가 S 의 부모와 어긋날 수 없다. 거부되면 새 끝에서 다시 만들어 게이트를 다시 돌리고 한 번 재시도한다. force push 는 하지 않는다.
4. **검증(각각 별도 명령).** 하나라도 어긋나면 §9 의 복구로 간다.
   - `origin/main` 이 P 뒤 정확히 1 커밋이고, 그 트리가 검토한 브랜치 끝과 같다.
   - legacy ref 둘이 P 를 가리킨다.
   - prototype 태그가 캡처 커밋을 가리킨다.
   - S 에 성공한 프로덕션 배포가 없다.
   - Actions 실행이 새 CI 하나뿐이다.
   - 프로덕션 지문이 F0 와 같다.
5. **정리.** 검증이 모두 초록인 뒤에만 작업 브랜치와 이 세션의 clone 을 지운다.
