    States that look like nothing

    Each of these is real, and none of them has an appearance. Drawing a tile for one would mean inventing the look.

    Interaction-blocked, hover-locked, inert. Three separate guards, and not one of them paints anything. tsx:1154 sets pointerEvents: 'none', :1134 sets inert in keyboard mode, and :1099 writes data-hover-lock-blocked as a QA anchor with no style attached. A blocked card is pixel-identical to an open one. That is the design — the block exists to keep a transition deterministic, not to tell the user anything — so if you find yourself reaching for a dim or a cursor change here, the state you want is unavailable, which is a different card.

    Real thumbnail asset vs. generated placeholder — no difference either. Checked byte for byte on 2026-09-07: the one shipped asset, public/landing-card-media/qmbti/thumbnail.svg, is the same artwork as the runtime fallback at tsx:166 — the same warm→sage gradient and the same two circles at the same coordinates. Only the delivery path and an added <title>/<desc> pair differ. So the product renders exactly one illustration across all eight cards today, which is what the tiles above show. Real per-variant artwork exists in the older design system and is imported, unrealized, in a later unit.

    Mobile OPENING / OPEN / CLOSING. Visually distinct, and deliberately not drawn here: the mobile expanded card is a full-bleed sheet with its own header, close control and scrim, which is a card of its own rather than a tile in a matrix. tsx:959-961, module.css:235-294.

    Motion states — enter, steady, exit, and the reduced-motion substitution — are in the Motion Lab, where they run at the realized 280ms and can be slowed to 0.125× to be judged. A still tile cannot show a curve. ViveTest Motion Lab →

    Never: a disabled-button treatment on a blocked card, a spinner or skeleton on any card face, a dimmed title or subtitle anywhere, or a badge announcing a state the surface already carries.
